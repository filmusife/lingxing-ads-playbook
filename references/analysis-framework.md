# 分析框架（产品匹配优先）

不要把“ACOS 高 = 否定、ACOS 低 = 加码”当主规则。广告要服务三件事，优先级是：

1. **相关搜索上的转化**（喂 Listing 搜索权重）
2. **自然流量 / 小类 BSR**
3. ACOS 作为成本约束，不是目的

不要把上述机制称为“A9”或“亚马逊最新官方算法”。亚马逊没有对外公布可引用的最新公式。对用户说明：这是可观察的工作假设——相关 query 转化好、错品点击少、核心大词出单稳，自然位和小类才更容易往前。

功能差、产品阶段、竞品赢面的完整判定表读 [feature-lifecycle.md](feature-lifecycle.md)。冷却、快照差分和串品类隔离读 [cooldown-snapshot.md](cooldown-snapshot.md)。**规则对任意品类生效**；下文研磨器只是例子。**没写完功能卡和阶段卡，不准出加码/否定/打竞品页的结论。**

## 1. 产品画像

从 Listing/属性表抽出，写进报告开头：

- 品类与**小类 BSR 节点**（权重落在这个节点，不是大类）
- **阶段**：用 `open_date`、`first_order_time`、评分数、7/14/30 销量斜率、广告占比、库存来定（冷启动 / 爬坡 / 成熟 / 老品防御 / 高库存 / 缺货）。券后价美化 CVR 时，阶段往早判，不往熟判
- **功能卡**：形态/架构、已验证功能、明确没有、差异化、这些差异化在主图/标题/前两点是否可见
- 价格栈：成交价 / 划线 / 券 / 是否促销中
- 评分、评分数（决定对比页社会证明，不是决定功能匹配）
- 日均销量走势、广告单占比、可售天数、库龄、在途

然后列两张表：

- **IS**：应该花钱并追求 TOS 的 query 家族（主粮 + 页面可见的差异化）
- **IS NOT**：即使用户搜索量高、甚至偶然出单，也要否定或停（不同形态、做不到的功能、错品类）

例：刀片咖啡研磨器 IS = electric coffee grinder / spice grinder / silent / 品牌词；IS NOT = burr、cordless、herb grinder（大麻）、removable bowl（若属性为否）、espresso machine。Listing 标题写了 espresso 只说明**相邻能转**，不代表小类主粮。

用户若提供属性表，以属性表和后台 Listing 为准，不要用广告词反推功能。脚本 `buckets.tsv` 只是弱先验，手册按功能卡重分。

## 2. 意图桶

把每条搜索词、关键词分进：

| 桶 | 处理 |
|---|---|
| 核心相关 | 独立精准，抬有效 TOS 竞价 |
| 品牌 | 单独品牌仓，允许较高 TOS |
| 功能卖点（静音、大容量、定时、可拆碗、双模式…） | 必须是已验证且页面可见；出精准，中等 TOS |
| 相邻能转（标题覆盖但不是小类主粮） | 保留低预算，不扩、不冲 TOS |
| 错品 / 本品做不到 | 否定或暂停，即使 ACOS 低、即使出过单 |
| 竞品品牌词 | 默认否；只有「竞品品牌 + 我们独有可见功能」且 CVR 接近搜索水平才单独低预算评估 |
| ASIN 对比 | 走赢面矩阵，不看“价格差不多” |

“相邻能转”常见于：刀片机打 espresso、吸尘器打蒸汽拖把同义词、配件打整机。能出单，但会把 Listing 推到错误人群，差评风险更高，对目标小类的自然流量帮助有限。

功能词额外规则：页面没有对应卖点 → 不加码，**先不否**（除非功能卡写明本品明确没有），第 8 节写 Listing 配合。不要用广告去教育一个主图上看不见的功能，也不要因为该功能词 ACOS 差就当错品清掉。

## 3. 位置与基础竞价

用户可见文本一律写**基础竞价**，不要写 BID。

```
搜索顶部实际竞价 ≈ 基础竞价 × (1 + TOS%/100)
```

若还开着动态提高竞价，实际 CPC 会再高一截。优化期优先固定竞价。动态提高+降低在发现仓、新品仓禁用。

若 CPC 是基础竞价的 2–3 倍，说明几乎只在顶部成交。此时：

- 发现/收割/自动：先把 TOS 从 200–300 降到 50–80
- 核心大词：提高 **基础竞价**，同时把 TOS% 降下来，让有效顶部竞价略升或持平，ROS 才有钱
- **禁止**在 TOS 300% 时把基础竞价从 0.30 提到 0.50（顶部会翻到 $2）

这条规则只适用于**当前后台 TOS 仍然虚高**。若 2–7 天前已经把 TOS 从 200–300 降到 80/160，30 天 CPC 仍可能是基础竞价的 2–3 倍——那是旧溢价污染，不是再砍一刀的证据。先拆改后 3–7 天 CPC；冷却期内第 3 节写「维持」。

TOS% 与 TOS 份额要一起看，不要只加溢价：

- TOS% 已经高，但 TOS 份额仍极低（例如 130% 溢价、份额 0.2%）→ 基础竞价低于市场，再加溢价无效。先降 TOS%，再抬基础竞价
- 核心 IS、CVR 健康、TOS 份额低、预算没花满 → 抬基础竞价
- TOS 份额已经高，但 CVR 差 → 买到了不转化的顶部点击，降 TOS%，查功能匹配和 Listing
- 老品自然位已稳定前 3 的 exact：可降该词 TOS，避免掏自己自然点击

商品页溢价（PP）只对**赢面矩阵为进攻**的 ASIN 有意义，对搜索权重帮助有限。ASIN 仓 TOS/ROS = 0。

**位置溢价一致性：** 手册里先写总表。后文每个活动的 TOS/PP/ROS「改成」必须与总表同一行完全相同。不允许总表写 80/30/50、详情里又写 120/60/80。

关键词没有单独基础竞价时，跟广告组默认基础竞价。改默认 = 改组里所有未单独定价的词。必须先列出哪些词有自己的基础竞价，禁止只改默认却以为只动了一条大词。

## 4. 活动角色

先给每个活动定性，再改。阶段不同，允许存在的角色不同（见 feature-lifecycle.md 第 5 节）。新品冷启动不要套成熟期的 8 仓齐全。

| 角色 | 典型名字 | TOS | 预算 |
|---|---|---|---|
| 核心精准 | 大词 exact 单活动 | 中高，但靠抬基础竞价不靠 250%+ | 保证花得动 |
| 品牌精准 | 品牌词 | 可偏高 | 中 |
| 功能精准 | 卖点 exact，且页面可见 | 中 | 中 |
| 收割 exact | “出单词” | ≤80 | 中，稳定赢家要迁走 |
| 发现广泛 | 手动广泛 | ≤70 | 中，核心 exact 要否定防抢量 |
| 自动紧密 | close match | ≤80 | 小 |
| 自动宽泛/拣漏/同类 | loose / substitutes | 0 单或错品就暂停 | 0 |
| SBV | 真视频 | 轻量，不当销量引擎 | 常远小于日预算，该降 |
| 商品集 | 名称叫 SBV 但创意是 COLLECTION | 按商品集留，不要当视频砍 | 有单且相关才留 |
| ASIN | 竞品页 | PP 可留，TOS/ROS = 0 | 只留赢面=进攻的 |
| SD / 受众 | 再营销或类目受众 | 不喂搜索权重 | 0 单或与自动重复就停 |

日预算远高于日耗 = 瓶颈在基础竞价/相关性，不是加预算。  
日预算花尽但核心 TOS 份额极低 = 先看垃圾仓/重复仓是否在抢预算。

重复投放：同一 exact 既在收割仓又在独立高 TOS 仓时，留数据更好的那条，暂停另一条，并在发现/自动里 exact 否定。同一 audienceId 开两条受众活动只留 CVR 更好的那条。

投放不足 3 天、花费还没到 3×日预算的新活动，除非明显 IS NOT 或完全重复，否则不要暂停。

## 5. 加码 / 否定阈值（必须叠加产品匹配 + 阶段 + 本品 CVR）

窗口默认 **30 天**。否定要慎重：样本不够就写“观察/先暂停”，不要装成定论。

**期望 CVR** = 本品搜索类广告（核心+功能，排除错品/ASIN/竞品品牌）的中位 CVR。不要用别的品类的绝对点击数。0 单判定用 `3 / 期望CVR` 次点击作暂停线（期望 12% ≈ 25 点击；期望 4% ≈ 75 点击）。新品冷启动再放宽一档，优先暂停不否定。

- **迁出独立精准**：30 天订单 ≥5、ACOS ≤ 目标上限、属于 IS、且页面能支撑该词
- **加基础竞价**：核心 IS、ACOS 低于目标、TOS 份额很低、日预算没花满、阶段不是缺货
- **降基础竞价 / 降 TOS**：ACOS 高于目标但仍是 IS；或 TOS 份额高但 CVR 差。该杠杆 7 天内刚改过则锁住，改用改后窗口验收，不要用 30 天混合数连调
- **暂停关键词**：词本身相关，但点击已达暂停线、0 单 → 先暂停 7 天，不立刻否定。大词（searchrank 低）即便 0 单，也优先查曝光/TOS 份额够不够，不够就先抬基础竞价，不要暂停当否词预演
- **否定**：优先 IS NOT（本品做不到的形态/功能）。相关词 0 单不要急着否。IS NOT 且点击已达暂停线才否。**强相关 + 数据差不是否定理由**
- **ASIN 暂停 / 保留 / 降基础竞价**：只走赢面矩阵（形态 → 对方主卖点我们有没有 → 可见差异化 → 评分数差 → 价格 → 实测 CVR）。禁止“价格接近所以留”，也禁止“价格接近但打不过所以否”。同形态有可见差异化、CVR 偏差 → 降基础竞价/降 PP；形态或主卖点输了 → 暂停
- **竞品品牌**：默认否
- **大词加基础竞价**：searchrank 在本品词表里属于头词/躯干词，IS，TOS 份额低或曝光明显低于同类头词，预算没花满 → 抬基础竞价，不要因为 CPC/ACOS 难看就否

目标 ACOS 用户没说时：用近期健康核心词的 ACOS 当锚，再按阶段放宽或收紧。冷启动可比成熟期高 10–20 个点。常见家电成熟期 22–25% 只是锚，咖啡机等低 CVR 品类不要硬套研磨器的锚。有明确利润目标就用用户的。记住：达标 ACOS 但核心大词订单掉、自然位掉，算失败。

库存可售天数 > 90 且销量在掉：多砍错品，少砍核心量。可售天数 < 21：不要扩发现，停 ASIN/SBV。

## 6. 诊断漏斗（先匹配，再数值）

每条要动的词/活动按这个漏斗写理由，禁止跳到 ACOS：

1. **形态/功能匹配吗？** 不匹配 → 否或停，后面数字无意义。匹配但页面看不见该卖点 → 不加码、不否，写 Listing 配合。
2. **阶段允许这个动作吗？** 冷启动不要否相关词、不要打 10 倍评分数头部 ASIN；缺货不要扩。
3. **这条词的搜索量/竞争度如何？** 用 `keyword_analysis.tsv` 的 `searchrank`（ABA 搜索频率排名，越小量越大）。没有 searchrank 就标 `DATA_MISSING`，用 30 天曝光作代理。禁止编周搜索量。量级按**本品词表内相对分层**（head/torso/tail），不要拿咖啡机的绝对排名去套配件。
4. **高曝光低 CTR**：相关性或主图/标题问题，不是加基础竞价能修的。先查 query 是否 IS、主图是否像搜索意图。
5. **低曝光 + 大词 + IS**：竞争大或基础竞价/位置不够，默认抬基础竞价或把低基础竞价+虚高 TOS 改成「够用的基础竞价 + 合理 TOS」，**禁止否定**。
6. **高 CTR 低 CVR**：人点进来但不买。查价格、评论、功能是否对得上 query、配送、页面有没有这个卖点。匹配错了才否；匹配对了就写 Listing 配合或降基础竞价观察，不要靠加价硬打，也不要当垃圾词否掉。
7. **CVR 健康但 TOS 份额低、预算没花满**：抬基础竞价，同时把虚高 TOS% 降下来。
8. **CPC >> 基础竞价**：溢价过高或动态加价，先拆位置溢价。若溢价刚降过，先标「30 天污染」，不要当成新的第 0 天止血。
9. **间接订单明显高于直接**：有光环，IS 词不要因为直接 ACOS 略高就否。
10. **促销期数字漂亮**：只解释，不作为扩量依据。

### 6.1 IS 词数据差时怎么选动作

| 功能卡 | 量级 | 曝光 / TOS 份额 | CTR | CVR/订单 | 动作 |
|---|---|---|---|---|---|
| IS，页面可见 | 头词/躯干 | 明显偏低 | 任意 | 差或 0 单 | 抬基础竞价 / 修 TOS 结构，不否、不停 |
| IS，页面可见 | 头词/躯干 | 已经高 | 低 | 任意 | Listing/主图/标题对不齐意图，不加价，不否 |
| IS，页面可见 | 任意 | 已经高 | 高 | 低 / 0 单 | 降基础竞价观察或暂停 7 天；第 8 节可写 Listing，不否 |
| IS，页面不可见 | 任意 | 任意 | 高 | 低 | 不加码、不否，Listing 先补卖点 |
| IS | 长尾 | 点击已达暂停线 | 任意 | 0 单 | 先暂停 7 天，不否 |
| IS NOT | 即使是大词 | 任意 | 任意 | 即使出过单 | 否定或暂停 |
| 竞品 ASIN | — | — | — | CVR 差 | 先赢面矩阵，再选降基础竞价还是暂停 |

`waste.txt` 里出现 `*_do_not_negate` 或 `head_term_*` 时，手册否定列表必须跳过这些词。

## 7. 权重逻辑（工作假设，非官方公式）

自然搜索和 Listing 权重，看的是 **该 query 是否相关、是否转化**，不是店铺广告总单，更不是 ACOS 数字本身。

- 小类要往前：核心大词的订单和 CVR 必须稳住，TOS 份额过低就加有效顶部竞价
- 错品点击会打脏相关性和转化，即使偶尔出单也伤害自然流量
- 商品页跟卖几乎不喂搜索权重
- 广告占比 70%+ 时，有机位弱，更要清洁 query，而不是用无关词堆销量
- 功能不匹配的“出单”会带来差评，差评再打 CVR，比高 ACOS 更伤权重

## 8. 改动顺序

第 0/1/3/7 天是**相对上一次改动**的日历，不是每次重跑都从第 0 天重新砍 TOS。若上次手册的位置溢价/基础竞价 2 天前刚落地，今天不是新的第 0 天，而是上次改动的第 2 天验收。

**第 0 天（止血）**：只处理**当前后台仍存在**的出血点。暂停明确亏损且 IS NOT 的活动；只否定 30 天里证据够硬的 IS NOT；赢面=暂停的 ASIN 当天停。发现/收割/自动 TOS 仅当**现在后台仍是 200–300% 这类虚高**才降。若 3–7 天内已经按上次手册降过（例如 230→80、250→160），今天不要因为 30 天 CPC 仍高再降一档。核心大词基础竞价仍然不动。

**第 1 天**：仅当该仓位置溢价不在冷却中，才允许「降 TOS% + 抬基础竞价」。若 TOS 刚降过、基础竞价刚加过，第 1 天改成验收，不要再叠加。收割仓稳定赢家可迁到对应精准仓，并在发现仓 exact 否定。不要同一天既否词又给该家族加薪。

**第 3 天**：核心大词订单掉 >30%（相对**改后**日均，不是相对 30 天日均）只把基础竞价加 0.05，不加 TOS%。

**第 7 天**：冷却到期。这时才允许用改后 7 天窗口决定要不要二次调整 TOS/基础竞价。看核心大词订单、小类 BSR、错品花费、自然单占比，而不是只看组合 ACOS。促销若在这周结束，先看 CVR 再动核心价。不要重开今天仍判暂停的 ASIN，除非赢面矩阵变了。

单次基础竞价变动不超过约 15–20% 或 $0.05（取对核心词更温和的那个），除非明显低于市场且 TOS 份额接近 0。不要同一天改完所有东西。同一杠杆 7 天内不要连调两次。

## 9. 历史调整、冷却锁、30 天污染

每天重跑不等于每天都要改后台。30 天是滞后窗口，刚改过的杠杆在窗口里会被旧设置淹没。不先对历史，就会把「已经降过的 TOS」再砍一刀。

### 9.1 诊断前必须对照（自变量差分，不靠 CPC，不靠运营日记）

Amazon Ads / 领星报表规则：

- **指标（因变量）** 才是历史：花费、CPC、曝光、点击、订单
- **属性（自变量）** 永远是此刻快照：`placement_top`、`bid`、`daily_budget`、`state`
- 所以不能靠“拉 9/18 的报表看那天基础竞价”。9/18 返回的 bid/TOS 仍是查询当下的值

证据优先级：

1. **配置快照差分。** 每次分析把当前自变量写入 `~/.codex/skills/lingxing-ads-playbook/state/{profile}_{ASIN}.json`，下次比对。看到 TOS/PP/ROS、日预算、启停、默认基础竞价、关键词基础竞价变了，才确定运营改过。锁该杠杆 7 天，手册写「维持」。词的基础竞价变了只锁词价，不要把整个活动 TOS 一起锁死。
2. **领星运营日志** `analytics_log_list_v2`。501/502/504 给改动日和对象，没有 before/after 数字。505 否定不锁溢价。第一次跑还没有旧快照时，用日志锁。
3. 用户口述。
4. 本地上次手册，只找回「改成」数字。

**不要做的：** 用 CPC 或花费跳变当“设置改过了”。CPC 会因 PP 流量变多、大促竞价、自然位波动而自己跳。`daily_breaks.tsv` 只用来拆改后观察窗口。

第一次跑：只存快照，没有差分是正常的。第二次及以后才有 `config_diff.tsv` 的 `160 → 90` 这种行。

### 9.2 冷却锁

非紧急默认：

| 杠杆 | 冷却 | 7 天内禁止 |
|---|---|---|
| TOS / PP / ROS | 7 天（最短 3 天） | 同一活动连砍或连加溢价 |
| 默认基础竞价 / 关键词基础竞价 | 7 天（最短 3 天） | 刚加完又加、刚降完又降 |
| 日预算 | 7 天（最短 3 天） | 刚降预算又降，或刚加预算又加 |
| 启停（非 IS NOT） | 3 天观察 | 刚暂停的相关仓当天重开 |

紧急例外，随时可动：硬 IS NOT 否定；暂停错形态/打不赢 ASIN；exact 多仓自相残杀；缺货；IS NOT 活动还开着。这些不喂 30 天 CPC，不占冷却。

冷却期内也不许把上次改动原路加回去。例如 2 天前 TOS 250→160，今天既不能再砍到 90，也不能加回 250，除非改后窗口已经证明核心大词日单腰斩。

### 9.3 30 天污染怎么拆

改动发生在窗口末尾时，30 天合计几乎全是旧设置：

- TOS 2 天前 250%→160%，30 天 CPC 仍高：约 28 天旧顶部溢价，不是 160% 仍然太高
- 基础竞价 2 天前 0.30→0.50，30 天 TOS 份额仍低：份额被改前 28 天拉低，不能据此再抬或再叠溢价
- 预算 2 天前下调，30 天花费仍高：同样是旧窗口

正确拆法：

1. 30 天窗口继续用来否 IS NOT、看意图桶、看竞品赢面（这些不受「刚改 TOS」影响）
2. 刚动过的位置/基础竞价/预算，另看**改后完整日**（不含改当天，至少 3 日，最好 7 日）
3. 改后样本不够时，结论是「维持并验收」，不是「按 30 天再调一档」
4. 报告里必须写一句：30 天 CPC/ACOS 含旧设置，不能作为二次调整证据

### 9.4 重跑出什么报告

- 上次手册 < 7 天：默认 **delta/验收**。第 3 节冷却行「改成」= 维持。聊天先讲锁哪些、补做哪些、今天不要动位置。
- 上次手册 ≥ 7 天：可出完整手册，但仍带「相对上次手册」表。已落地杠杆不要包装成新发现。
- 合格的每天重跑：检查上次改动有没有执行、改后核心单有没有掉、IS NOT 有没有清掉。不是每天给一套新的 TOS 矩阵。
